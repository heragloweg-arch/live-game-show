# Sprint 2 — تقرير أمان قاعدة البيانات

التاريخ: 18 أكتوبر 2026
المستودع: `heragloweg-arch/live-game-show`
قاعدة البيانات: مشروع Supabase الحالي (لا فرع جديد)

## التغييرات المنفذة
- أضيفت migrations `20261018015606_lockdown_client_table_privileges.sql`, `20261018015744_separate_public_profile_view.sql`, و`20261018015849_public_profile_allowlist_rpc.sql` إلى `main`، بأرقام متطابقة مع سجل Supabase.
- طُبقت المهاجرات الثلاث على قاعدة البيانات الحالية؛ المهاجرة الثانية تاريخية وأنشأت view مؤقتة، والثالثة أزالتها واستبدلتها بـ RPC آمن.
- أُزيلت صلاحيات `TRUNCATE`, `TRIGGER`, و`REFERENCES` من أدوار `PUBLIC`, `anon`, و`authenticated` عن كل جداول public؛ هذه الصلاحيات لا ينبغي أن تكون متاحة لعميل التطبيق، وTRUNCATE لا تحكمه سياسات RLS.
- سُحبت صلاحية استخدام schema `private` والتنفيذ المباشر لدالة `private.is_current_user_room_member(uuid)` من أدوار العميل.
- أزيلت سياسة قراءة كل صفوف `profiles`، وسُحبت صلاحية قراءة الجدول الأساسي من `anon`، وأُنشئت دالة `get_public_profiles` كواجهة عامة محدودة الحقول، دون العملات أو خطة الاشتراك أو تاريخ انتهائه أو حالة onboarding. أُزيلت محاولة العرض التي أثار advisor بسبب تجاوزها RLS، واستُبدلت بدالة SECURITY DEFINER ذات `search_path` مثبت وقائمة أعمدة صريحة.
- عُدلت واجهات المتصدرين والخصوم الأخيرة لاستخدام `get_public_profiles` بدل قراءة صفوف الملف الخاص.
- أُضيفت تأكيدات تمنع نجاح migration إذا وُجد جدول public بلا RLS.
- أضيف ملف فحوص SQL لتأكيد الصلاحيات وRLS وsearch_path لدوال SECURITY DEFINER.

## نتيجة التحقق بعد التطبيق
- 57 جدولًا في schema public.
- RLS مفعّل على 57/57 جدولًا.
- 0 جدولًا بقيت عليه صلاحيات عميل غير آمنة من نوع TRUNCATE/TRIGGER/REFERENCES.
- anon/authenticated لا يستطيعان استخدام schema private أو تنفيذ دالة العضوية الداخلية.
- دالة `get_public_profiles` تعيد الأعمدة العامة المسموح بها فقط؛ والقراءة المباشرة لجدول `profiles` متاحة للمستخدم المسجل وفق RLS الخاص بصفه.
- 0 دوال SECURITY DEFINER في public/private بلا search_path مثبت.
- المهاجرات الثلاث مسجلة في سجل Supabase بالإصدارات `20261018015606`, `20261018015744`, و`20261018015849`.

## ما لم يُغلق بعد
- 16 جدولًا عليها RLS بلا سياسات؛ هذا يمنع الوصول عبر RLS افتراضيًا، لكن يجب مراجعة ما إذا كانت كل حالة مقصودة وتوثيقها.
- لا تزال هناك سياسات تسمح بقراءة بعض بيانات اللعب العامة، ويجب مراجعة كل سياسة وفق عقد البيانات المقصود.
- لا تزال اختبارات التكامل بحسابات مستخدمين حقيقيين مطلوبة، بما فيها المالك/غير المالك والمستخدم المحظور والمشرف.
- لا يعني نجاح فحوص SQL أن Sprint 2 مغلق بالكامل؛ يلزم تشغيل CI النهائي، واختبارات واجهة/تكامل بحسابات حقيقية، ومراجعة سياسات الجداول الستة عشر ذات default-deny.
