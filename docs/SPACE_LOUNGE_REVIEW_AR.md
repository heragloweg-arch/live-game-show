# مراجعة فنية وتصميم استراحة الفضاء — 10 نوفمبر 2026

## خلاصة القرار

راجعت ملفات الفريق المشتركة: `lounge.html` و`lounge.css` و`lounge.js` و`space-lounge-cinematic(5).html`، إضافة إلى موجز التكليف ومصدر تطبيق «قدها». هذه الملفات نماذج مستقلة وليست مكونات React جاهزة؛ لذلك احتفظت بها مرجعًا بصريًا ولم أدمجها أو أستبدل بها مسارات اللعبة. أضيفت الاستراحة كاختيار منفصل من الرئيسية، مع إبقاء التحديات والمواجهة ودورة النقاط كما هي.

## الرؤية الفنية

اعتمدت اتجاه **«مقهى مداري حيّ»**: مشهد low-poly ثلاثي الأبعاد لطيف يقرأه مشاهد البث بسرعة، لا لوحة HUD نيون مزدحمة. الكاميرا isometric واسعة ومائلة من أعلى لتُظهر الأرضية والشخصيات المجسمة معًا؛ تحافظ على اتساعها خلال الحركة الجماعية، ولا تُقرّب إلا بقدر محدود حتى تبقى الشخصيات واضحة في إطار الهاتف. الأسماء وملصقات الحركة وحالة البث طبقة HTML عربية منفصلة كي تبقى مقروءة فوق المجسمات.

المشهد يضم منصة رقص حلقية، بوابتي دخول وخروج، مقاعد قليلة، وخمسة أفعال قصيرة: رقص، شقلبة، جري، فوضى، وانعدام جاذبية. الألوان كحلية ليلية، والفيروزي للتفاعل، والذهبي للداعم أو الراعي فقط. صُممت النسب لشاشة OBS عريضة ولعرض عمودي 9:16، مع fallback عند تعذر WebGL واحترام إعداد تقليل الحركة.

## التصميم والأداء

- بطاقة «استراحة الفضاء» ومساراتها كسولة التحميل؛ لا يُستورد موصل TikTok في متصفح اللاعب، ولا يعمل المشهد قبل فتح الاستراحة.
- Three.js تبعية MIT في chunk منفصل بلغ في build الأخير **545.6 KB minified / 137.51 KB gzip**، ولم تُدرج في PWA precache. هذا يحافظ على تحميل الصفحة الرئيسية، لكنه يعني تنزيلًا إضافيًا عند أول فتح للساحة؛ ويظهر تحذير Vite المعتاد لحجم chunk فوق 500 KB.
- حد المشهد الحالي 24 شخصية نشطة. الاستقبال البسيط لأحداث TikTok يتم في عامل Node مستقل وبجلسة واحدة، وليس 500 اتصال من المتصفح.
- إذا كان جمهور TikTok اليومي 500 مشاهد، فالمشاهدون لا يحتاجون فتح التطبيق أو إنشاء WebSocket؛ تكفي غرفة بث واحدة وعميل overlay واحد. إذا تجاوز المتصلون بالساحة 24 مشاركًا في الوقت نفسه، سيُرفض الانضمام الإضافي. لم يُجرَ اختبار ضغط لـ500 اتصال متزامن.

## ما أُضيف لتكامل LIVE

- عامل Node مستقل في `services/space-lounge-worker` يستخدم `tiktok-live-connector@2.5.0` ويستهلك أحداث Webcast على الخادم ثم يرسل snapshots إلى overlay عبر SSE.
- لا يتصل العامل إلا بعد جلسة مضيف مصادق عليها عبر Supabase ووجود معرّف المضيف في allowlist. أضيف مسار لاستعادة الجلسة وإعدادات الهدايا بعد تحديث لوحة المضيف، ويستعيد الشاشة الراعي أيضًا.
- يدخل المشاهد بكلمة يحددها المضيف. للتحكم في شخصيته يطلب رمزًا عشوائيًا من ثمانية أرقام، يكتبه بنفسه في تعليق `!verify <code>`، ثم يستطيع سحب مركبته على خريطة المدار؛ أزرار الاتجاه تبقى بديلًا. يعيد الخادم الموضع الحقيقي عند التحقق. المضيف يستطيع تحريك الجميع.
- قواعد Gift ID فارغة افتراضيًا ولا تُخمّن؛ يضيفها المضيف يدويًا، وتُعالج نهاية الهدية المتسلسلة مرة واحدة فقط. تُعرض بطاقة الراعي والنشاط والداعمين دون نقاط مسابقة.
- الحضور والأسماء ومعرّفات TikTok الخام ونصوص التعليقات مؤقتة في ذاكرة العامل؛ لا يستخدم العامل `service_role` ولا يحتفظ بسجل المشاركين بعد نهاية الجلسة. لا يوجد حفظ دائم لتفضيل المظهر أو أمر `!forget` بعد.
- لم يُنفذ QR، ولا تذكير الراعي المجدول كل 15 دقيقة، ولا تفضيلات مظهر دائمة. تبقى هذه عناصر مفتوحة في `TODO.md` ولا تُسوّق على أنها مكتملة.

## حدود المكتبة والترخيص

اختيرت المكتبة المجانية بناءً على توجيه مالك المنتج بتاريخ 8 نوفمبر 2026. `tiktok-live-connector` تستخدم بروتوكول Webcast غير رسمي، وليست TikTok LIVE API رسمية، ولا تضمن ثبات الأحداث أو استمرار خدمة التوقيع المجتمعية المجانية. أحداث المغادرة غير موثوقة؛ لذلك ينهي الخمول حضور المشارك تدريجيًا. الهدايا التي تفتقد `msgId` ثابتًا تُهمل لمنع التكرار.

الحزمة مرخّصة بـ`AGPL-3.0-only` مع إشعار/شروط إضافية تتعلق بالاستخدام المستضاف. أُرفق نص الترخيص والإشعار داخل العامل. قبل تشغيل خدمة شبكة أو استخدام تجاري يلزم نشر المصدر المطابق للعامل ومراجعة قانونية للترخيص وشروط TikTok. لا يعني وجود الشيفرة محليًا موافقة قانونية أو اتصالًا حيًا.

## نتائج الاختبار المحلي

- التطبيق: `npm run typecheck` و`npm run lint` — ناجحان.
- Vitest: **26 اختبارًا ناجحًا**؛ بوابات الإنتاج `npm run test:production-gates`: **50 اختبارًا ناجحًا**.
- عامل TikTok: `npm test` — **19 اختبارًا ناجحًا**، بينها استعادة الجلسة، إثبات الهوية، إرجاع موضع الشخصية، أمان claims، تنظيف الحضور، معالجة chat/gift اصطناعيًا، وعقد استعادة HTTP بمصادقة Supabase وهمية.
- Smoke HTTP محلي: صحة العامل 200 مع LIVE مغلق؛ CORS المسموح 204 والمرفوض 403؛ مسار الجلسة دون إعداد Auth يرفض 503. مع query strings بقيت حدود `/healthz` و`/events` مرتبطة بالمسار الصحيح (91 طلب صحة يصل إلى 429، و100 طلب إلى مسار events لم تحصل على 429 زائفة).
- اختبار عقد الاستعادة مع Supabase Auth محلي وهمي نجح: `/api/sessions/active` يعيد `session` و`overlayToken` و`giftRules` حتى عند غياب جلسة نشطة، ونجح اختبار مدير الجلسة باستعادة قواعد الهدايا المحددة.
- Build إنتاجي محلي نجح بقيم Supabase شكلية غير سرية. حزمة Three.js بقيت خارج قائمة PWA precache.
- `npm audit --omit=dev` للتطبيق الرئيسي: **صفر ثغرات إنتاجية**.
- `npm audit --omit=dev` لعامل TikTok: **صفر ثغرات إنتاجية**.
- لا تستخدم هذه الاختبارات حساب TikTok أو بثًا فعليًا؛ اتصال LIVE الحقيقي واختبار الشبكة المستضافة لم يُنفذا.

## ما يلزم قبل التفعيل

لم يُنشر العامل أو يُدفع تغيير إلى الفرع الرئيسي/Railway. يلزم نشر خدمة مستقلة ثم إعداد الأسرار/المتغيرات عبر لوحة المنصة—not في المحادثة أو ملفات المصدر—وضبط `ENABLE_TIKTOK_LIVE=false` إلى حين إتمام مراجعة الترخيص، ثم إضافة `SUPABASE_URL` و`SUPABASE_ANON_KEY` و`SPACE_LOUNGE_ALLOWED_HOST_IDS` و`SPACE_LOUNGE_ALLOWED_ORIGINS` للعامل، وضبط `VITE_SPACE_LOUNGE_WORKER_URL` في build الواجهة. يختبر المالك حساب LIVE الذي يملكه بنفسه أولًا.
