# مسار Cohort المحتوى الذهبي — قدها

## قاعدة الإطلاق

لا يعني اجتياز فحص البنية لـ968 سؤالاً أن 968 سؤالاً صالحة معرفياً أو جاهزة للتفعيل. التفعيل التشغيلي يتم على Cohortات صغيرة، كل manifest بحد أقصى 50 سؤالاً، حتى نصل إلى 300 سؤال ذهبي بعد مراجعة بشرية موثقة.

## التسلسل

1. اختيار 25–50 سؤالاً من الصفوف غير النشطة.
2. مراجعة الصياغة والحقائق والمصدر والخيارات والإجابة.
3. مراجعة دينية إضافية لكل `subtype=religion`.
4. إنشاء manifest يحوي `challengeId` و`reviewerId` وأعلام المراجعة.
5. تشغيل `npm run content:approve-batch -- manifest.json` على Staging أو Internal فقط.
6. تسجيل عدد الصفوف ووقت الاعتماد واسم المراجع دون أسرار.
7. تشغيل مباريات مراقبة قبل إضافة Cohort جديد.
8. عدم اعتماد `production` مباشرة؛ المسار المسموح هو `staging → internal → soft_launch`.

## حماية الأداة

- الحد الأقصى للدفعة الواحدة 50 سؤالاً.
- يمنع تكرار `challengeId` داخل manifest.
- يمنع التفعيل المباشر للإنتاج.
- لا يمر الاعتماد إلا عبر RPC محمي بـservice role.
- المحتوى الديني يحتاج `religiousReviewed=true`.

## تعريف 300 سؤال ذهبي

لا تُعلن Cohort 300 مكتملة إلا بوجود 6 دفعات كحد أقصى 50، ولكل سؤال:

- إجابة/خيارات صالحة.
- مراجعة بشرية مسجلة.
- مصدر عند الحاجة.
- locale وdifficulty وtags.
- عدم وجود تكرار أو سؤال حر بلا عقد إجابة.

**الحالة الحالية:** البوابة البرمجية جاهزة، لكن الاعتماد البشري والتفعيل على Staging/‏Internal لم يُنفذا في هذه الجلسة.
