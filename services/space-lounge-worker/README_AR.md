# عامل استراحة الفضاء — TikTok LIVE

خدمة Node منفصلة عن React وخادم الملفات. لا يتصل المتصفح بTikTok؛ يستقبل العامل Webcast عبر `tiktok-live-connector` ثم يرسل snapshots مختصرة إلى مشهد OBS عبر SSE. كل حضور/اسم/رمز تحكم/ترتيب هدايا مؤقت في الذاكرة فقط، ويُمحى عند إغلاق الجلسة.

## التشغيل المحلي الاصطناعي

```sh
cd services/space-lounge-worker
npm ci
npm test
npm start
```

يبدأ الخادم بوضع LIVE مغلق افتراضيًا؛ `/healthz` يعرض `tiktokEnabled:false`. يمكن اختبار دورة الجلسة باستعمال `ENABLE_TIKTOK_LIVE=true` مع إعداد المشرف وSupabase وعنوان بث تجريبي يملكه المستخدم. لا تشغّل الاتصال على حساب أو بث لا تملكه.

## متغيرات البيئة

انسخ `.env.example` إلى ملف محلي غير متعقّب. الحد الأدنى للتشغيل الحي:

- `PORT`: منفذ HTTP، افتراضي `8080`.
- `ENABLE_TIKTOK_LIVE=true`: مفتاح تشغيل صريح؛ القيمة الافتراضية تعطل إنشاء جلسة LIVE.
- `SUPABASE_URL` و`SUPABASE_ANON_KEY`: يستخدمهما العامل للتحقق من access token عبر Supabase Auth `/user`، وليس لتعديل قاعدة بيانات.
- `SPACE_LOUNGE_ALLOWED_HOST_IDS`: قائمة معرفات مستخدمي Supabase المخوّلين، مفصولة بفواصل.
- `SPACE_LOUNGE_ALLOWED_ORIGINS`: أصل/أصول HTTPS الدقيقة المسموح لها بطلبات المتصفح، مفصولة بفواصل.

على إعداد بناء واجهة React، أضف `VITE_SPACE_LOUNGE_WORKER_URL` مساويًا لعنوان العامل العام. هذا متغير عنوان غير سري، لكنه يُضمّن في نسخة الواجهة وقت البناء؛ بدونه تبقى شاشة المضيف معاينة ولا تطلب اتصالًا.

لا يحتاج العامل إلى `service_role` أو cookie/session TikTok أو `VITE_*` أو بيانات دخول TikTok. يضع المضيف اسم LIVE/handle فقط، ويستعمل الموصل غير المصادق عليه. لا يمكن ضمان عمل البروتوكول غير الرسمي أو بقاء الخدمة المجتمعية المجانية لتوقيع الاتصال متاحة دائمًا.

## واجهات HTTP

- `GET /healthz`: صحة الخدمة ووضع LIVE الحالي فقط.
- `GET /api/sessions/active` (Bearer لمضيف allowlisted): يستعيد الجلسة وإعدادات الهدايا ورمز OBS للمضيف نفسه بعد إعادة تحميل اللوحة؛ لا يكشف جلسة مضيف آخر، ويعيد `session: null` عند عدم وجود جلسة.
- `POST /api/sessions/start` (Bearer access token لمضيف allowlisted): `{tiktokHandle, joinKeyword, durationMinutes, title?, sponsorLabel?}`؛ المدة 60–90 دقيقة. يعيد snapshot وtoken عشوائي للقراءة فقط؛ يبني التطبيق رابط OBS `/space-lounge/overlay/:sessionId#access=...`، ويرسل الرمز في Authorization لا في URL عند فتح SSE.
- `POST /api/sessions/:id/stop`: إنهاء الجلسة ومسح الحضور المؤقت.
- `GET /api/sessions/:id/events` مع `Authorization: Bearer <overlayToken>`: SSE للـoverlay المخوّل؛ يرسل snapshots عامة دون TikTok user IDs أو رموز تحكم، والرمز لا يوضع في URL.
- `POST /api/sessions/:id/claim`: `{}`؛ يعيد رمزًا عشوائيًا من 8 أرقام صالحًا 3 دقائق؛ ينشره المستخدم بنفسه في تعليق `!verify 12345678`، ولا يطلب اسمًا يدويًا.
- `POST /api/sessions/:id/claim-status`: `{claimId}` داخل body؛ يعيد سر التحكم مرة واحدة فقط بعد مطابقة التعليق إلى TikTok user ID في الحدث الخادمي، ولا يضع معرف المطالبة في URL.
- `PATCH /api/sessions/:id/participants/:participantId`: يحرك المشارك أو يغير مظهره، مع `X-Participant-Control` الذي لم يُكشف قبل التحقق.
- `PUT /api/sessions/:id/gift-rules` (المضيف): حفظ قواعد Gift IDs الفعلية التي دخلها المضيف يدويًا. لا توجد أي قاعدة افتراضية.
- `POST /api/sessions/:id/scene-action` (المضيف): تحريك كل الشخصيات القائمة خمس ثوانٍ في مشهد جماعي.

يُضاف `SPACE_LOUNGE_ALLOWED_HOST_IDS` كمعرف مستخدم موثوق، ويُسمح بـCORS فقط للأصول المعلنة. دخول الساحة يبقى مجانيًا بكلمة `joinKeyword`; الهدية لا تنفذ إلا إذا عُيّن Gift ID حقيقي صراحة.

يطبق العامل سقفًا عامًا قدره 12,000 طلب HTTP في الدقيقة، مع حدود أدق لمسارات التحقق والحركة وSSE. يوجد حد 80 اتصال SSE متزامنًا و24 شخصية مرئية؛ جمهور TikTok لا ينشئ اتصال متصفح لكل مشاهد ما لم يفتح صفحة التحكم بنفسه. هذه أرقام النسخة الأولى وليست اختبار تحمل أو ضمانًا لخمسمئة اتصال متزامن.

## حدود التكامل

`member`, `chat`, `gift`, `disconnected`, و`error` أحداث مكتبة غير رسمية مبنية على Webcast الداخلي، وليست TikTok LIVE API رسمية. لا يفترض العامل وجود حدث مغادرة موثوق؛ يغادر المشارك بعد 5 دقائق خمول مع تعيين موقعه عند بوابة الخروج. الهدايا التي لا تحمل معرّف حدث ثابتًا تُهمل لتجنب إعادة تنفيذ أثرها عند التكرار؛ والهدايا المتسلسلة تُعالج عند `repeatEnd` فقط، وبقية Gift IDs تتجاهلها الخدمة. يحتفظ عامل واحد بجلسة واحدة و24 شخصية كحد أقصى؛ هذا الحد مخصص لبث يومي في حدود مئات المشاهدين وليس ضمان تحمل 500 اتصال SSE متزامن.

قبل نشر خدمة على Railway/أي منصة مستضافة أو تشغيل تجاري، انشر كامل مصدر العامل والنسخة المطابقة للعامل وفق الترخيص، واطلب مراجعة قانونية لتوافق `AGPL-3.0-only` والاستثناءات الإضافية. المجلد `licenses/` يحوي نسخة الترخيص التي وصلت مع الحزمة؛ هذا ليس رأيًا قانونيًا. لا يُعد وجود الشيفرة محليًا تصريحًا بالنشر.

اختبار اتصال حقيقي لم يُنفذ. يلزم ضبط URL وبيئة آمنة ثم تجربة LIVE بحساب وبث يملكهما المستخدم، ومراقبة الاستقرار/حدود Euler قبل إظهار أن الخدمة متصلة.
